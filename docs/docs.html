Overview

A VS Code extension for encrypting and decrypting MuleSoft secure configuration properties without leaving your editor. All cryptography runs locally. Keys and KeyIdentifier names are held only in VS Code’s secret storage and are never transmitted.

The extension bundles three tools, all reachable from the MuleSoft AES icon in the activity bar:

ToolAlgorithmsModesRandom IVEditor integration
MuleSoft AES Encrypt / DecryptAES-128 / AES-256CBCNo (derived IV)Toolbar, right-click, whole-file workflow
Secure Properties Encrypt / DecryptAES, Blowfish, DES, DESede, RC2, RCACBC, CFB, ECB, OFBOptionalSidebar and Command Palette
Base64 Encode / Decode———Sidebar and Command Palette

The two encryption tools are independent screens. With its defaults (AES / CBC / no random IV), the Secure Properties tool produces output that is byte-for-byte identical to the AES tool, so the two are interchangeable for standard values.

Quick start

From the sidebar

  1. Click the MuleSoft AES icon in the activity bar.
  2. Open Settings and configure your encryption keys.
  3. Pick a tool: MuleSoft AES Encrypt / Decrypt for standard AES/CBC values, or Secure Properties Encrypt / Decrypt for other algorithms, modes or random IVs.
  4. Enter your text, choose a KeyIdentifier (and, for Secure Properties, the algorithm, mode and IV settings), then click Encrypt or Decrypt.
  5. Use Copy to Clipboard to grab the result.

In a YAML or properties editor

  1. Open a .yaml, .yml or .properties file.
  2. Select a value, right-click, and choose MuleSoft AES: Encrypt Selection or MuleSoft AES: Decrypt Selection.
  3. Or click MuleSoft AES: Encrypt / Decrypt File in the editor toolbar to open the whole-file workflow beside the editor.

Tools

MuleSoft AES Encrypt / Decrypt

The streamlined option for projects using MuleSoft’s standard AES configuration.

  • MuleSoft compatible: AES-128-CBC or AES-256-CBC with PKCS5 padding.
  • Key-driven strength: a key of exactly 32 characters selects AES-256. Any other key, including 16 or 24 characters, uses AES-128. There is no AES-192 mode in this tool; use Secure Properties if you need it.
  • Derived IV: taken from the first 16 characters of the key, so encryption is deterministic: identical input always yields identical output.
  • Output format: ![base64EncodedString], ready to paste into MuleSoft config files.
  • Decrypt input: accepts raw Base64 or the wrapped ![…] format.
  • Opens beside the editor from the toolbar, so your file stays visible.
PropertyValue
AlgorithmAES-128-CBC or AES-256-CBC
Block size128 bits
PaddingPKCS5
IVDerived from the first 16 characters of the key
Output encodingBase64, wrapped in ![ … ]

Keys must be at least 16 characters. Use exactly 32 characters to get AES-256; longer keys fall back to AES-128 using their first 16 bytes.

Secure Properties Encrypt / Decrypt

A full-featured tool that goes beyond the standard AES/CBC workflow.

Use it when your configuration needs a different algorithm (Blowfish, DES, DESede, RC2 or RCA), a cipher mode other than CBC (CFB, ECB or OFB), or random initialization vectors for non-deterministic encryption. The interface follows the same layout as the AES tool, with an extra options row.

Options

ControlTypeChoicesDefault
AlgorithmDropdownAES, Blowfish, DES, DESede, RC2, RCAAES
State (Mode)DropdownCBC, CFB, ECB, OFBCBC
Use Random IVsCheckboxOn / offOff

Adaptive controls

The options row prevents invalid combinations:

  • ECB uses no IV, so Use Random IVs is disabled.
  • RCA (RC4) is a stream cipher with no mode and no IV, so both State (Mode) and Use Random IVs are disabled.

See the algorithm reference for key requirements and the modes & IVs reference for how IVs are handled. You can also explore the matrix interactively.

Base64 Encode / Decode

Quick text and file Base64, next to your keys.

  • Encode plain text or files to Base64.
  • Decode Base64 strings back to plain text.
  • Drag and drop or browse for files, and copy results to the clipboard.

In file mode, Decode reads from the output box (where the encoded Base64 was produced or pasted), not from the file-drop input. Paste or edit the Base64 there before decoding.

In the editor

Editor toolbar

Two toolbar buttons appear automatically when you edit .yaml, .yml or .properties files:

ButtonCommandOpens
Encrypt / Decryptaes.encryptDecryptThe main MuleSoft AES screen, beside the editor
Encrypt / Decrypt Fileaes.fileEncryptDecryptThe whole-file workflow, beside the editor

The Secure Properties tool has no editor toolbar button or context-menu entry by design. Open it from the sidebar or the Command Palette.

Selection actions

Select a value in a supported file, right-click, and choose MuleSoft AES: Encrypt Selection or MuleSoft AES: Decrypt Selection. A quick pick asks you to Select a KeyIdentifier or input key:

  • Pick a saved KeyIdentifier (only those with a key configured are listed), or
  • Choose Input key manually to type a one-off key that is used for this operation only and never stored.

Only the selected text is replaced. These entries appear only in the editor context menu, and only when text is selected in a .yaml, .yml or .properties file.

Whole-file workflow

Encrypt or decrypt many fields in the active file with a single edit.

  1. Click MuleSoft AES: Encrypt / Decrypt File in the editor toolbar. The panel opens beside the editor.
  2. Choose Encrypt or Decrypt.
  3. Choose a KeyIdentifier (its key is shown masked, as on the main AES screen) or input a key manually.
  4. Tick the fields you want. The Select all checkbox selects or clears every row; nothing is selected by default.
  5. Click Encrypt selected values or Decrypt selected values to apply every replacement in one edit.

Each row shows the field name on the left, and its value (truncated past 120 characters) plus the full path and line number on the right. A logo button in the panel header opens the main AES tool.

  • Encrypt mode lists plain scalar values that are not already wrapped in ![ … ].
  • Decrypt mode lists complete secure values only, including quoted ones such as "![…]" and '![…]'.
Keys

Key management

Both encryption tools draw from the same set of KeyIdentifiers, managed from the Settings screen in the sidebar.

  • Presets for common environments: DEV, FIT, UAT and PROD.
  • Custom KeyIdentifiers: add your own named keys.
  • Ordering: drag rows by their handle, or use the Move up / Move down buttons from the keyboard, to set the order used in every KeyIdentifier dropdown.
  • Secure storage: keys live in VS Code’s built-in secret storage and never leave the machine.
  • Visibility toggle: show or hide keys, with partial masking.

Selecting a KeyIdentifier fills in (and masks) its key, and locks the field to that value. Typing, pressing Backspace / Delete, or pasting into the field switches the dropdown back to Custom and clears it, so you can enter a one-off key without reselecting Custom first. Changes saved in Settings refresh any open encryption panels automatically.

Save a key from the encrypt screen

When you type a custom key, a save button (disk icon) appears between the show/hide toggle and the KeyIdentifier dropdown. Click it, enter a Key Identifier name and save. The key is stored in secret storage and added to the dropdown on both encryption screens immediately. In the dialog, press Enter to confirm or Esc to cancel.

Refresh keys

Each encryption screen has a refresh button in the top-right corner that reloads KeyIdentifiers from storage, so new keys appear without closing and reopening the panel.

Algorithms

Every algorithm in the Secure Properties tool shares one floor enforced by the UI: keys must be at least 16 characters. Some ciphers only consume a prefix of the key; the rest is ignored.

AlgorithmDescriptionIV sizeKey requirement
AESAdvanced Encryption Standard (default)16 bytes16 / 24 / 32 chars → AES-128 / 192 / 256
BlowfishBruce Schneier’s block cipher8 bytes≥ 16 chars (up to 56 bytes used)
DESData Encryption Standard (legacy)8 bytes≥ 16 chars (only the first 8 bytes used)
DESedeTriple DES (3DES)8 bytes≥ 24 chars
RC2Rivest Cipher 28 bytes≥ 16 chars
RCARC4 / ARCFOUR stream cipherNone≥ 16 chars

Unlike the Secure Properties tool, the standalone AES tool does not support AES-192. A 24-character key there still resolves to AES-128, using only its first 16 bytes.

Cipher modes & IVs

ModeNameUses an IV?
CBCCipher Block Chaining (default)Yes
CFBCipher FeedbackYes
ECBElectronic CodebookNo
OFBOutput FeedbackYes

Initialization vectors

  • Derived IV (default): the IV is the first N characters of the key, where N is the algorithm’s IV size (16 for AES, 8 for the others). Encryption is deterministic, matching the AES tool.
  • Random IV (checkbox on): a cryptographically random IV is generated for each encryption, prepended to the ciphertext before Base64 encoding, and read back automatically during decryption. Each run produces different ciphertext, which is generally more secure.

Output format

All output is wrapped in MuleSoft’s secure-properties format, ![base64String]. With random IVs enabled, the IV bytes sit at the front of the payload inside the wrapper, keeping each value a single, self-contained token.

# application.yaml
db:
  password: "![IC/nBJeEeAJg7vYzxVCcYJ+3DJZpthwL114HH38lEhM=]"

Decrypt input accepts raw Base64, the wrapped ![…] format, and values surrounded by double or single quotes (YAML requires quotes around ![…] because a bare ! is a tag indicator).

Runtime availability

Ciphers run through Node.js and OpenSSL as provided by the VS Code runtime.

  • Always available: AES (all modes) and DESede (all modes).
  • May require the OpenSSL “legacy” provider: Blowfish, DES, RC2 and RCA (RC4).

If the runtime can’t provide a selected algorithm, the tool returns a clear, non-crashing error, for example Cipher "bf-cbc" is not supported by this runtime, rather than failing silently. The full algorithm set is always offered for fidelity with the MuleSoft generator.

Help

Examples

Encrypt a selected database password

  1. Open application.yaml.
  2. Select myDatabasePassword, right-click, and choose MuleSoft AES: Encrypt Selection.
  3. Select the PROD KeyIdentifier, or input the key manually.
  4. The selection is replaced in place:
db:
  password: ![EncryptedValueHere]
  connectString: "![EncryptedValueHere]"

Encrypt several values in a file

  1. Open application.yaml or application.properties.
  2. Click MuleSoft AES: Encrypt / Decrypt File in the editor toolbar.
  3. Keep Encrypt selected, choose a KeyIdentifier or input a key, and tick the fields to encrypt (or use Select all).
  4. Click Encrypt selected values to apply every replacement in one edit.

Decrypt selected secure values in a file

  1. Open the file workflow beside a YAML or properties editor and switch to Decrypt.
  2. Choose the same KeyIdentifier or manual key used for encryption.
  3. Tick the secure values to decrypt (or use Select all) and click Decrypt selected values.

Encrypt with random IVs (Secure Properties)

  1. Open Secure Properties Encrypt / Decrypt from the sidebar.
  2. Choose an algorithm and mode (for example AES / CBC) and check Use Random IVs.
  3. Select a KeyIdentifier or type a custom key, enter your secret, and click Encrypt. Encrypting the same value twice yields two different tokens that both decrypt to the original.

Decrypt an existing value

  1. Paste the ![ … ] value into Input Text.
  2. Select the KeyIdentifier used to encrypt it.
  3. In the Secure Properties tool, also match the algorithm, mode and Use Random IVs setting that produced the value.
  4. Click Decrypt.

Security

  • Keys are stored in VS Code’s secure storage, which maps to the OS keychain: Windows Credential Manager, macOS Keychain, or pass / Secret Service on Linux.
  • All encryption and decryption happens locally. No keys or data are sent over the network, and there are no external API calls.
  • Keys are partially masked in the UI.

Best practices

  1. Use strong keys. 32 characters is recommended and unlocks AES-256.
  2. Prefer random IVs for new secrets where your MuleSoft runtime supports them.
  3. Rotate keys periodically in production.
  4. Use different keys per environment (DEV / FIT / UAT / PROD).
  5. Avoid legacy algorithms (DES, RC2, RC4) for new data. They exist for compatibility with existing values only.

Found a vulnerability? Please report it privately through GitHub’s security advisories rather than a public issue.

Troubleshooting

Blowfish / DES / RC2 / RCA returns “not supported by this runtime”.

These legacy algorithms depend on the OpenSSL “legacy” provider, which may not be enabled in your VS Code runtime. AES and DESede always work; use AES for new secrets.

Decrypted output is garbage, or decryption fails.

Make sure every setting matches the values used to encrypt: the key or KeyIdentifier and, in the Secure Properties tool, the algorithm, mode and Use Random IVs option.

The same input gives a different encrypted value each time.

That’s expected when Use Random IVs is checked. Uncheck it for deterministic output.

An encryption key isn’t saving.

Confirm VS Code can access secret storage, then restart VS Code.

The AES editor buttons don’t appear.

They only show for .yaml, .yml and .properties files. The Secure Properties tool has no editor button by design; open it from the sidebar.

No fields appear in the file workflow.

Encrypt mode lists plain scalar values that aren’t already wrapped in ![ … ]. Decrypt mode lists complete secure values only.
