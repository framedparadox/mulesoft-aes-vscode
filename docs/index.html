Privacy and security

Your secrets never leave your machine. No servers. No accounts. No telemetry. Just OpenSSL, your OS keychain, and your editor.

Local cryptography

Every operation runs in-process through Node.js and OpenSSL, provided by VS Code itself.

Keys in your keychain

Stored in VS Code’s SecretStorage. Never in settings.json, never in your workspace.

Zero network calls

No external APIs, no analytics, no telemetry. It works the same on a plane as it does at your desk.

Open source

MIT licensed. Every line that touches your secrets is on GitHub for you to read.

Good habits, a click away.

Best practices from the documentation. The extension makes each one easy to follow.

  1. Use 32-character keys. They unlock AES-256.
  2. Prefer random IVs for new secrets where your MuleSoft runtime supports them.
  3. Keep one key per environment: DEV, FIT, UAT and PROD.
  4. Rotate production keys periodically.
  5. Leave DES, RC2 and RC4 for legacy values. Don’t use them for new data.

Questions? Answers.

Is the output compatible with MuleSoft’s Secure Properties tool?

Yes. Every value uses MuleSoft’s ![base64] secure‑properties format. The AES tool matches MuleSoft’s standard AES/CBC setup with an IV derived from the key, and the Secure Properties tool mirrors the generator’s algorithms, modes and random‑IV option.

Does the extension send my keys or data anywhere?

No. All encryption and decryption happens locally. There are no network requests, no external APIs and no telemetry. Keys are held only in VS Code’s secret storage, which maps to your operating system’s keychain.

Why do I get a different result every time I encrypt?

That’s expected when Use Random IVs is on in the Secure Properties tool. A fresh IV is generated for each value and stored at the front of the token, so every result differs but they all decrypt to the same text. Turn it off for deterministic output.

Blowfish, DES, RC2 or RCA says “not supported by this runtime.” Why?

Those legacy ciphers depend on OpenSSL’s “legacy” provider, which may not be enabled in your VS Code runtime. The extension reports a clear error instead of failing silently. AES and DESede always work, and AES is the right choice for new secrets.

Can I use AES-192?

Yes, in the Secure Properties tool: a 24‑character key selects AES‑192. The standalone AES tool only produces AES‑128 or AES‑256, so a 24‑character key there resolves to AES‑128 using its first 16 bytes.

Decryption fails or returns garbage. What should I check?

Every setting has to match the one used to encrypt: the key or KeyIdentifier and, in the Secure Properties tool, the algorithm, mode and Use Random IVs option.

The editor buttons don’t appear.

They only show for .yaml, .yml and .properties files. The Secure Properties tool deliberately has no editor button. Open it from the sidebar or the Command Palette instead.

Is this an official MuleSoft product?

No. It’s an independent, open‑source project and isn’t affiliated with, sponsored by or endorsed by MuleSoft or Salesforce.
