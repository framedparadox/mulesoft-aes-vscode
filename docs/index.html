Interactive Instructions

Step-by-Step How-To Guides

Detailed walkthroughs for every encryption, decryption, batch, and management workflow.

1

Open MuleSoft AES in Activity Bar

Click the MuleSoft AES shield icon on the VS Code Activity Bar on the far left of your screen. If hidden, open the Command Palette (Ctrl+Shift+P or Cmd+Shift+P) and run View: Show MuleSoft AES.

2

Configure Environment Keys in Settings

Click MuleSoft AES: Settings in the sidebar. Enter keys for your environments (DEV, FIT, UAT, PROD). Keys are automatically encrypted in your local OS Keychain via VS Code SecretStorage.

Preset Names: DEV, FIT, UAT, PROD | Recommended key length: 32 characters for AES-256
3

Choose Your Encryption Screen

Select MuleSoft AES Encrypt / Decrypt for standard AES/CBC values, or Secure Properties Encrypt / Decrypt for Blowfish, 3DES, or random IVs.

4

Encrypt or Decrypt & Copy

Enter your plaintext, select the target KeyIdentifier (e.g. PROD), and click Encrypt. Click Copy to Clipboard to grab the ![base64] value ready for your MuleSoft configuration files.

1

Open your MuleSoft YAML or Properties file

Open any application.yaml, application.yml, or application.properties configuration file in VS Code.

2

Highlight the Secret Value

Select only the property value you wish to protect (e.g. mySuperSecretPassword123), without selecting the key name or indentation.

3

Right-Click & Select Encrypt Selection

Right-click the highlighted text. In the context menu, click MuleSoft AES: Encrypt Selection.

4

Pick KeyIdentifier or Manual Key

A QuickPick menu pops up at the top of your editor. Choose from your saved KeyIdentifiers (e.g., PROD) or select Manual Key. The editor automatically replaces the value in place with quotes preserved:

db: password: "![aBcD1234EncryptedValue==]"
1

Click the Editor Toolbar Button

In the top-right corner of any .yaml or .properties editor tab, click the MuleSoft AES: Encrypt / Decrypt File icon.

2

Review Candidate Fields

The panel opens automatically beside your code. In Encrypt mode, it parses scalar plain values. In Decrypt mode, it parses complete ![...] secure values.

3

Select Fields or Use "Select All"

Check the individual fields you wish to transform, or click the master Select all checkbox to toggle all rows at once. Each row shows field path, truncated value, and exact line number.

4

Execute Batch Transformation

Choose your KeyIdentifier and click Encrypt selected values (or Decrypt). All replacements are committed in a single atomic editor transaction.

1

Open Secure Properties Encrypt / Decrypt

Open from the Activity Bar sidebar or run MuleSoft Secure Properties Encrypt / Decrypt from the Command Palette.

2

Choose Algorithm and Mode

Select your algorithm from the dropdown: AES, Blowfish, DES, DESede (3DES), RC2, or RCA (RC4). Select mode: CBC, CFB, ECB, or OFB.

3

Toggle "Use Random IVs"

Check the Use Random IVs checkbox. A cryptographically random initialization vector is generated per execution and prepended directly to the ciphertext.

Result format: ![ <16-byte random IV> + <ciphertext> ] base64 encoded. Encrypting "mySecret" twice yields two completely different tokens!
4

Transparent Decryption

To decrypt a random-IV token, simply keep Use Random IVs checked. The tool automatically reads the prepended IV bytes from the front of the payload.

1

Open Base64 Encode / Decode

Click Base64 Encode / Decode in the sidebar. Choose either the Text or File mode tab.

2

Text Encoding / Decoding

Type or paste string data into Input Text, then click Encode or Decode. Easily copy output with 1 click.

3

File Drag & Drop

In File mode, drag any binary certificate, keystore, or text file into the drop zone or click Browse. The file is read via FileReader locally in memory and encoded instantly.

4

File Mode Output Decoding

When decoding in File mode, the tool reads from the output box where the Base64 string was produced or pasted, ensuring a seamless round-trip.

Deep Architecture

Cryptographic Matrix & Technical Specifications

Exact parity rules, cipher parameters, and runtime availability guidelines.

Algorithm Description IV Size Key Requirement Supported Modes OpenSSL Runtime Provider
AES (Default) Advanced Encryption Standard 16 bytes 16 / 24 / 32 chars → AES-128 / 192 / 256 CBC, CFB, ECB, OFB Always Built-in
Blowfish Bruce Schneier 64-bit block cipher 8 bytes ≥ 16 chars (up to 56 bytes consumed) CBC, CFB, ECB, OFB Requires OpenSSL Legacy
DES Data Encryption Standard (Legacy) 8 bytes ≥ 16 chars (first 8 bytes consumed) CBC, CFB, ECB, OFB Requires OpenSSL Legacy
DESede Triple DES (3DES) 8 bytes ≥ 24 chars (24 bytes consumed) CBC, CFB, ECB, OFB Always Built-in
RC2 Rivest Cipher 2 variable-key block 8 bytes ≥ 16 chars (16 bytes consumed) CBC, CFB, ECB, OFB Requires OpenSSL Legacy
RCA (RC4) ARCFOUR stream cipher None ≥ 16 chars (up to 256 bytes consumed) Stream (No mode/IV) Requires OpenSSL Legacy

The Key-Driven Strength Rule

In the dedicated MuleSoft AES Encrypt / Decrypt tool:

  • A key of exactly 32 characters selects AES-256-CBC.
  • Any key from 16 to 31 characters (or > 32) selects AES-128-CBC.
  • There is no AES-192 mode in the standard AES screen. For true AES-192, use the Secure Properties tool with a 24-character key.

Initialization Vector Mechanics

Deterministic vs. Non-Deterministic execution:

  • Derived IV (Default): IV is derived from the first 16 characters of the key (or 8 chars for 64-bit block ciphers). Output is deterministic.
  • Random IV: crypto.randomBytes() generates a fresh cryptographically random IV per run, prepending it to the ciphertext before Base64 encoding.

YAML Quoting & Unwrapping

Why quotes matter in MuleSoft YAML files:

  • In YAML, an unquoted exclamation mark ! denotes a custom YAML type tag. Therefore, secure properties must be enclosed in double or single quotes: "![...]".
  • The extension's unwrap parser automatically strips outer quotes and unwraps the inner ![...] envelope cleanly.

        Security Architecture
        
Zero Telemetry. 100% Local Execution.

        

          Designed for regulated enterprises, banks, healthcare, and security-conscious MuleSoft teams.
        

      


      

        

          

            
          

          
No Network Calls

          

            All cryptographic operations execute locally using Node.js / OpenSSL in the VS Code runtime.
            Not a single byte of your keys, properties, or payloads ever leaves your workstation.
          

        


        

          

            
          

          
Hardware & OS Key Vault

          

            Saved keys are stored via VS Code SecretStorage, backed by:
            macOS Keychain, Windows Credential Manager, or Linux Secret Service (gnome-keyring / KWallet / pass).
          

        


        

          

            
          

          
Shoulder-Surfing Defense

          

            Key previews are partially masked by default (e.g. MySec**********456).
            Disk-backed webview state serialization is deliberately omitted to prevent caching plaintext secrets on disk.
          

        

      

    

  


  
  

    

      

        Troubleshooting & FAQ
        
Frequently Asked Questions

        

          Instant answers to common operational questions and configuration edge cases.
        

      


      

        
        
      


      

        
        

          

            Why do I get "Cipher 'bf-cbc' is not supported by this runtime"?
            
          

          

            Legacy ciphers like Blowfish, DES, RC2, and RC4 depend on OpenSSL's legacy provider. Some VS Code builds disable this provider by default. AES and DESede (3DES) are always built-in and supported everywhere. For all new projects, AES-128 or AES-256 is strongly recommended by MuleSoft.
          

        


        
        

          

            Why does encrypting the same text give a different output each time?
            
          

          

            That is expected when Use Random IVs is checked. A new cryptographically random IV is generated for every encryption pass and prepended to the ciphertext. Both tokens will decrypt to the exact same plaintext when decrypted with the same key. For deterministic tokens, uncheck "Use Random IVs" or use the standard AES Encrypt / Decrypt tool.
          

        


        
        

          

            Why don't the AES buttons appear in my editor toolbar?
            
          

          

            Editor toolbar buttons and right-click context menu actions are conditionally registered to appear only when editing .yaml, .yml, or .properties files. Ensure your file extension matches or set the VS Code language mode to YAML or Properties in the bottom status bar.
          

        


        
        

          

            Decrypted output is garbage or fails with a padding error.
            
          

          

            Decryption requires an exact match of all cryptographic parameters: the key string, algorithm, cipher mode (e.g. CBC vs ECB), and whether Random IV was used. If you encrypted with AES-256 (32-character key), you must decrypt with that exact 32-character key.
          

        


        
        

          

            Why does the Whole-File batch panel show no fields?
            
          

          

            In Encrypt mode, the scanner lists plain scalar values that are not already wrapped in ![...]. In Decrypt mode, it lists only complete ![...] tokens. If all values are already encrypted, the Encrypt field list will be empty.
          

        


        
        

          

            Can I save a one-off key directly from the encryption screen?
            
          

          

            Yes! When you type a custom key in either encryption panel, a save disk icon appears next to the KeyIdentifier dropdown. Click it, assign a name (e.g. SANDBOX), and press Enter. The key is saved to SecretStorage and immediately synced to all panels.
